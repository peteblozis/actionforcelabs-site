LESSON 08

Building a Prompt Library

You've made it through the seven lessons. You know how to be specific, when to set a role, why examples work, how to constrain format, how to iterate, and how to spot when things go wrong.

Now the goal is: stop reinventing prompts every time.

If you write a prompt that works well, save it. Reuse it. Improve it. That's a prompt library, and it's the difference between someone who's "good at AI" and someone who's fast at AI.

What to save

Save any prompt that:

  • You'll use more than twice
  • Took multiple iterations to get right
  • Produces consistently good output
  • Solves a recurring task in your work or life

Don't save one-off prompts. They clutter the library.

The simple system

You don't need fancy software. A folder of text files works. Or a Google Doc. Or Notion. Or a Notes app. Pick whatever you'll actually open.

For each prompt, save:

1. A one-line description ("Turns meeting notes into action items")
2. The prompt itself
3. A short note on when to use it ("Best for messy verbal notes,
   not for cleanly-structured ones")
4. An example of the input and output, so you remember what
   it produces

Templating with placeholders

The most reusable prompts use placeholders for the variable parts:

"Rewrite the following [TYPE OF TEXT] for [AUDIENCE].
 Goals: [GOAL_1], [GOAL_2].
 Constraints: under [WORD_COUNT] words. [TONE] tone.

 Text to rewrite:
 [PASTE TEXT HERE]"

You fill in the brackets each time. The skeleton stays the same. This is where most of the time savings come from.

Categories worth building

Most people end up with prompts in these categories:

  • Communication — emails, replies, follow-ups, declines
  • Writing — blog drafts, summaries, rewrites, proofreading
  • Thinking — pros/cons, decision frameworks, devil's advocate
  • Research — explain X to me, compare A and B, find counter-arguments
  • Personal — meal plans, gift ideas, trip planning
  • Work-specific — whatever you do all day, templated

The improvement loop

When a prompt fails or underperforms, don't just abandon it — fix it. Add a constraint. Add an example. Tighten the role. Then save the improved version.

Over months, your library compounds. The prompts you used 6 months ago are noticeably worse than the ones you're writing now. That's progress, not a problem.

Pete's filing rule

If you can't decide whether to save a prompt, save it. Storage is free. Searching is fast. The cost of saving a mediocre prompt is zero. The cost of not saving a good one is hours of recreation later.

A starter library — three prompts to save today

Copy these three into your library as a starting point:

1. EMAIL CLEANUP
"Rewrite this email to be 30% shorter while keeping all
information and a polite, direct tone. Remove filler.

[PASTE EMAIL]"

2. EXPLAIN-LIKE-I'M-SMART-BUT-NEW
"Explain [TOPIC] to me. I'm an intelligent adult who has
not encountered this before. Use 2 concrete examples.
Avoid jargon, but don't dumb it down. About 250 words."

3. DEVIL'S ADVOCATE
"I'm thinking about [DECISION]. Argue the strongest case
AGAINST it. Be specific. Don't soften the criticism. I'll
weigh your arguments against my plan, not adopt them."

Use each at least once this week. Modify them to fit your style. By the end of a month, you'll have 10–15 prompts you actually reach for.

You're done

That's the series. Eight lessons. The whole thing fits in one sentence: tell the AI what you actually want, show it an example, give it constraints, and iterate when it's close.

Everything else is practice.
